# Web-first implementation contract

This iteration uses the existing Expo web build and a separate local Node API. Native routes stay intact. All new browser UI lives in `web/`, rendered by `app/_layout.web.tsx`. Use semantic DOM and shared CSS classes; CSS is intentional for this web-only surface. No inline styles or `any` types. Refer to `web/types.ts` for exact data/action types.

Shared UI supplied by root in `web/ui.tsx`: `Button` (ordinary button props plus variant='primary'|'secondary'|'ghost'|'danger', busy?), `Card` (div props), `Badge` (children, tone?='green'|'blue'|'amber'|'red'|'muted'), `Empty` (title, description?, action?:ReactNode), `Modal` (title, onClose, children, wide?), `Field` (label, children, hint?), `PageHeader` (eyebrow?, title, description?, actions?), `Avatar` (name, size?='sm'|'md'|'lg'), `Icon` (name:string,size?:number), `Stat` (label,value,detail?), `ConfirmDialog` (title,description,onConfirm,onClose,busy?). Layout classes: page-stack, grid-2, grid-3, grid-4, panel, panel-header, row, row-between, stack, muted, small, eyebrow, divider, input, textarea, select, field, actions, card, list-row, empty, form-grid, chip, chip-active, status-dot, error-text, table-wrap. Use semantic headings/buttons/labels. Root owns CSS, message needed for extra classes.

`PageProps` includes state, run(action)->fresh WebState, navigate(route), refresh(), toast(message,kind?). Async mutations catch errors for visible feedback, disable repeated submissions. Confirm destructive actions. Do not call Supabase in this web layer.

Pages exported from assigned files: Member.tsx exports TodayPage, JournalPage, ProgressPage. Trainer.tsx exports CoachPage, ClientsPage. Programs.tsx exports PlansPage, StudioPage. Community.tsx exports DiscoverPage, MessagesPage, NotificationsPage. Account.tsx exports SettingsPage. All accept PageProps. Root owns authentication screens and router.

API: POST /api/auth/login {email,password}, POST /api/auth/register {name,email,password,role} -> {token,state}; POST /api/auth/logout; GET /api/state -> WebState; POST /api/action body Action -> WebState; GET /api/export -> account JSON; POST /api/generate body GenerationRequest -> {program:Program,provider:'local-template'}. Bearer token is stored per tab (sessionStorage) by root api.ts. Exports available from api.ts: generatePlan(request), exportAccount(), apiRequest<T>(path,options?). Account deletion clears token/root app after action returns state? Backend returns {deleted:true}; root run handles it and transitions to auth (returns prior state for type contract).

Demo sign-in: member@aigym.local / trainer@aigym.local, both password TrainToday!2026. Seed display names Alex Morgan and Jordan Lee. Backend seed includes active relationship, programs, occurrences and history to make dashboards useful. New registration starts honestly empty. Roles are member/trainer in this web contract; native client role mapping belongs to future adapter.

Dates are local calendar YYYY-MM-DD; mapping day uses JS convention 0 Sunday...6 Saturday. IDs generated via crypto.randomUUID. Weight always kg in persisted payloads. Workout completion is idempotent by stable workout.id; backend completes its occurrence atomically. Member session draft/outbox uses owner-specific localStorage keys and clears displayed state when identity changes. Pending operations stay attributed to original owner, never replay for another account.

Backend returns authorized state only. Public trainers expose only intended profile metadata (email blank). Pending relationships do not unlock private training history. Only request recipient can accept. Revocation stops trainer access. Program source server-derived from actor except explicitly local AI plans. Programs default private; assigned routine snapshots are available to member independent of future deletion. Notifications/read state and feedback persist on server. Node API listens on 127.0.0.1:8094 by default and serves exported web-dist; Metro dev uses 8093. Local persistence path .local-web/data.json (ignored), configurable AI_GYM_DATA_DIR/AI_GYM_PORT for tests. Never expose this local preview server publicly.
